# 原始词库与完整注册表范围

本目录供 `../build_catalog.py` 离线生成 `../../data/catalog.json`。

## 范围

- 版本固定为 **Minecraft Java 1.21.9**，没有混入其他正式版本、快照版或基岩版专属注册项。
- `block.json` 共 **1204** 条：全部 **1166** 个方块 ID，加上 **38** 个原有概念词条，包括无物品形式的方块、液体、空气、传送门、活塞头、墙上/盆栽形式和技术方块。
- `item.json` 共 **1509** 条：官方 `minecraft:item` 注册表的 **1488** 个 ID，以及原有的 **21** 个概念词条（剑、镐、船、染料等）。
- `mob.json` 共 **153** 条，覆盖全部 **153** 个实体类型 ID，包括生物、投射物、载具、展示实体、技术实体、玩家模型与玩家类型。沿用内部类别键 `mob`，界面显示「生物/实体」，「实体」与「生物」命令等价。
- 物品包括方块对应的物品、各材质装备、各木种/颜色变种、唱片、陶片、锻造模板、刷怪蛋等。
- **全部 2866 条均可成为答案**，`curation.json` 中三类 `unanswerable` 均为空；管理员物品、生成蛋、空气、不可生存获得的方块和仅命令生成的实体同样算。困难池覆盖每类的全部条目；简单/普通仍按难度分级。
- 一个注册 ID 对应一个词条；药水效果、附魔等级、书本内容、旗帜图案组合、自定义组件和任意方块状态组合不再无限拆分。

## 数据来源

三类清单、物品稀有度/堆叠上限、官方名称及配方/掉落数据使用 Mojang 游戏数据的 `misode/mcmeta` 提取结果：

- 仓库：<https://github.com/misode/mcmeta>
- 固定 summary 提交：`e85a17c2e574c2103b0f28da9c02219a81b53297`（`1.21.9-summary`）。
- 注册表：`registries/data.json`；默认物品组件：`item_components/data.json`。
- 原版配方与掉落表：`data/recipe/data.json`、`data/loot_table/data.json`；物品标签：`data/tag/item/data.json`。仅使用正式启用的数据，不导入 `data/experiment/`。
- 中英文名称：`1.21.9-assets` 中的 `assets/minecraft/lang/zh_cn.json` 与 `en_us.json`。
- 辅助历史信息：各正式版本的 mcmeta 注册表，以及 PrismarineJS/minecraft-data 的 1.7–1.13.2 物品及旧版元数据变种清单。其余历史、用途和可再生性沿用原有 mcdle 人工整理数据，并对具体变种细化。
- 原有概念数据来源与许可仍遵循项目根目录 README 中的 Minecraft Wiki / koishi-plugin-mcdle 说明；新增的游戏数据不改变已有内容的许可要求。

方块硬度、爆炸抗性、光照数据、默认几何标记和实体注册体型使用 PrismarineJS/minecraft-data 同版本游戏提取数据：

- 仓库：<https://github.com/PrismarineJS/minecraft-data>
- 固定提交：`9b995542ab4a17837dee785439954e43d031b33e`。
- 文件：`data/pc/1.21.9/blocks.json` 与 `entities.json`。
- 方块所用工具结合原版 `mineable/*` 方块标签；形状、燃烧与可再生性等使用原有种类资料并按具体形式细化。
- 生命实体的既有生命值沿用原始资料。新增盔甲架、玩家模型与玩家使用默认生命属性 20；这些类的继承与属性构建参考官方 1.21.9 客户端及映射，客户端 SHA-1 已记录。非生命实体统一用 0 表示该字段不适用，不将它伪装成有 20 生命值的生物。

`registry_1_21_9.json` 保存三类完整 ID 清单、保留概念 ID、固定提交、下载输入的 SHA-256 与 `all_entries` 答案策略。它不会被复制到运行时题库。

## 字段整理方法

- `id`：在各自类别与对应注册表逐项核对，包含全部 1166 / 1488 / 153 个注册 ID。
- `rarity`、`stackable`：注册项的**默认**物品组件值；附魔等动态组件可能改变游戏中的实际稀有度。
- `chinese_title`、`title`：新增注册项使用该版本官方语言文件。唱片追加曲目，纹饰锻造模板追加纹饰名称，避免不同 ID 同名；空地图和已填写地图的英文名作区分。既有概念词条及其译名修正继续保留。
- `recipe`：从正式配方的产物与配方类型提取；工作台、熔炉、高炉、烟熏炉、营火、切石机和锻造台分别记录。动态合成及交互不一定对应静态配方 JSON。
- `obtaining`、`loot`：结合配方、掉落表与原有分类资料；交易、装桶、地图使用等由对应物品种类规则补充。这些概括字段不逐一列出掉落条件、交易等级或概率。
- `usage`、`renewable`：在原有概念种类资料基础上，结合配方材料、材质、掉落及变种规则整理；并非官方组件中直接提供的属性。
- `inventory_categories`：现改为 Java 1.21.9 原版 `CreativeModeTabs` 的实际标签页内容，使用默认 feature flags 和管理员权限。排除搜索、已保存快捷栏、生存物品栏等非分类标签；保留一个物品所属的多个分类。方块通过原版 `Block.asItem()` 找到物品形态，实体统一为 `not_applicable`，不把刷怪蛋的分类当成实体分类。`op_blocks` 规范化为既有键 `operator_utilities`；显示名使用同版本官方简体中文。
- `dimensions`：自然生成的方块、自然出现的实体，以及物品直接采集/掉落/结构战利品的来源维度；不沿配方材料追溯，也不把玩家搬运、放置或命令当作维度来源。数据从该版本官方客户端内置的生物群系、噪声配置、特征、结构模板、结构池、处理器与掉落表提取，补充 Java 中硬编码的地物、结构和自然生成事件；下界废弃传送门先应用游戏真实的黑石替换表再统计。集合包含主世界、下界、末地，可有多个值。`none` 显示「无直接自然来源记录」，表示此口径下没有收录直接来源，不等于不能合成、制造、转化、召唤或用命令得到，也不是“禁止在任何维度存在”。
- `name_length`：按最终显示中文名（包括策展译名修正）统计 Unicode 字符，计标点、不计空白；构建时检查与显示名完全一致。名称含字反馈和含字问题使用同一显示名，不比较别名/英文名/ID，不泄露字的位置或重复次数。
- `variants`：仅有 `color`（颜色）、`type`（品种）、`none`（无）三个宽泛标签，前两者可同时存在，`none` 必须单独使用；不输出木种、材质等细分类型、成员名称或变体数量。依据固定 1.21.9 客户端的完整颜色系列、可染色标签、精选同类系列标签、实体变种注册表以及明确的内置变种规则整理；总称聚合其已有成员的标签，具体成员继承所在系列标签。不会因为共享任意 ID 前缀、可用同一种工具挖掘，或普通状态/年龄/氧化值不同就视为变体。`none` 表示不属于本次整理的系列，不是对任何自定义配置的绝对判断。
- `variant_families_1_21_9.json`：变体维护快照，记录固定客户端 SHA-1、系列成员与取证规则；系列名称、成员列表和数量不写入运行时属性或提示。通过 `python tools/enrich_raw_variants.py` 离线应用；维护者可追加 `--client <1.21.9-client.jar>` 从版本固定的客户端重建快照。该步骤只增改 raw 的 `variants` 与取值映射，再运行 `python tools/build_catalog.py` 生成题库。
- `context_1_21_9.json`：保存固定客户端 SHA-1、创造标签页、方块物品形态、黑石替换表、自然来源记录和概念词条所聚合的注册成员。概念词条的维度与创造分类取成员并集。缺少自然来源记录不能反向证明游戏中绝对不会出现；这些概括属性与既有机制属性一样，不是对全部世界种子、运行时状态和交互条件的穷举。
- `initial_release`：结合原有历史资料、旧版元数据变种与正式版本注册表判断；已知实验特性按正式发布版本修正，重命名不作为新增物品。较早版本的历史日期继承相应种类资料，未逐条重做 Wiki 历史考证。
- 方块 `stackable=0` 表示该方块没有对应的库存物品形式，显示为「无物品形式」；物品类别的 `air` 仍保留其默认物品组件值。
- 实体 `health=0` 表示没有适用的生命实体生命属性，显示为「不适用」，不是「已死亡」。投射物、掉落物等可能另有破坏机制或自己的 NBT 字段，不在这里假定为生物生命属性。体型高度来自注册基础尺寸；展示/交互实体可在运行时由数据修改，玩家姿态、幼体与实体缩放也不另列为新注册项。
- 沿墙的告示牌、旗帜、头颅、珊瑚扇与藤蔓植株等在官方语言中可能复用同名，词库增加形式限定以避免注册 ID 之间的歧义。旋风人与玩家发射的风弹也分别记录。
- 难度保持原有简单池；常见具体变种加入普通池，所有技术与管理员内容均保留在完整困难池中，不再排除答案。与具体注册名称冲突的旧别名已清除，避免猜测歧义。

因此，“完整”指**该版本三类全部注册 ID 均存在且能成为答案**，不代表每个词条已人工考证全部游戏机制，也不意味着枚举任意自定义数据配置。

## 重新生成与检查

在插件根目录执行：

```bash
python tools/build_catalog.py
python tools/build_catalog.py --check
```

构建不联网，具有确定性。注册表快照存在时，构建会拒绝任一类缺少注册项的数据，且 `all_entries` 策略会拒绝任何重新排除答案的策展配置；`--refresh` 也会在写文件前检查三类覆盖率，防止原来的概念数据源覆盖完整词库。

上下文快照更新后先运行 `python tools/enrich_raw_context.py`，再构建词库；这一步只更新 raw 中的维度、创造分类和名称字数，不改 ID、名称、难度或答案权限。维护者可用 `tools/extract_context.py --client <1.21.9-client.jar> --creative <creative_tabs.tsv> --output tools/mcdle_raw/context_1_21_9.json` 重新提取快照；客户端 SHA-1 必须匹配固定版本。创造 TSV 由随附的 `tools/ExtractCreative.java` 在 JDK 21、客户端及其官方运行库 classpath 下导出，输入标签 TSV 可用 `tools/resolve_vanilla_tags.py` 从同一客户端生成；下载游戏文件和 Java 库只用于离线维护，插件运行不需要 Java，也不会联网。

使用完整池：`/mc猜 开始 方块 困难`、`/mc猜 开始 物品 困难`、`/猜实体 困难`。
